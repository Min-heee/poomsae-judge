# 샘플 시퀀스가 어디서 왔는가

`public/samples/*.json` 은 촬영본이 아니라 **이 폴더의 코드가 만든 합성 랜드마크 시퀀스**입니다.

정직하게 먼저 적습니다. **합성 데이터는 판정 규칙이 옳다는 것을 증명하지 않습니다.**
규칙이 의도대로 동작하는지, 그리고 어제와 같은 답을 내는지만 증명합니다.
규칙의 타당성은 유단자 검토가 필요하고, 아직 받지 않았습니다.

## 왜 녹화가 아니라 합성인가

1. **결정성.** 녹화 영상에서 좌표를 뽑으면 그 좌표가 추론 백엔드와 모델 버전에 묶입니다.
   같은 입력에 같은 점수가 나와야 한다는 원칙(PRD 원칙 2)이 우리 손을 떠납니다.
2. **실패 케이스.** PRD F5의 완료 기준은 "일부러 손상시킨 샘플이 보류로 떨어지고
   이유·프레임 번호가 표시된다"입니다. 관절이 정확히 어느 구간에서 가려진 영상을
   찍어 오는 것보다, 좋은 샘플의 신뢰도를 그 구간만 깎는 편이 정확합니다.
3. **출처.** 공개 영상은 재배포·파생 허용 여부를 확인하기 어렵습니다.
   합성이면 "이 JSON이 어디서 왔는가"에 코드로 답할 수 있습니다.

## 다시 굽는 법

저장소 루트에서:

```bash
npx vite-node src/samples/write-samples.ts
```

`vite-node` 는 vitest 가 이미 끌고 오는 패키지라 따로 설치할 것이 없습니다.
시드가 고정돼 있으므로 누가 언제 돌려도 **같은 바이트**가 나옵니다.
그 성질은 매 테스트마다 확인합니다 — `src/samples/samples.test.ts` 가
커밋된 파일과 다시 구운 결과를 문자열로 비교합니다. 하나라도 어긋나면 테스트가 깨집니다.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `rig.ts` | 인체계측 분절 길이, 순·역운동학, 33개 랜드마크 조립, 시드 PRNG |
| `motion.ts` | 키프레임 + smoothstep 보간, 공개 샘플 5종의 동작 정의 |
| `degrade.ts` | 좋은 샘플을 일부러 망가뜨려 보류 경로용 샘플 2종을 파생 |
| `codec.ts` | JSON 스키마와 반올림(좌표 1e-4 m, 신뢰도 1e-2) |
| `build.ts` | 전부 굽고 manifest 를 만든다 |
| `write-samples.ts` | 파일로 쓴다 (위 명령이 실행하는 것) |
| `fixtures.ts` | **테스트 전용** 제조기. 경계값을 정확히 맞춘 입력을 만든다 |

공개 샘플(`motion.ts`)과 테스트 픽스처(`fixtures.ts`)를 갈라 둔 이유는 목적이 다르기 때문입니다.
공개 샘플은 사람이 보기에 동작처럼 보여야 하고(지터·시간 비대칭·가드 자세),
픽스처는 재려는 값이 설계값과 정확히 같아야 합니다(지터 0, 정점에 평평한 구간).
한 파일에 섞으면 어느 쪽 목적도 만족하지 못합니다.

## 좌표 약속

- 단위 **미터**, 원점 **엉덩이 중점**, **y는 아래로 증가**.
  MediaPipe `worldLandmarks` 의 규약에 맞춘 것입니다.
- 주춤서기는 **정면**(좌우 벌림이 x축), 앞차기는 **측면**(앞뒤가 x축, +x가 차는 방향).
  판정 규칙의 각도를 전부 화면 평면에서 재기 때문에, 어느 평면이 화면 평면인지가 규칙의 전제입니다.

뒤 두 개는 좌표가 원본과 **완전히 같습니다**. 동작이 아니라 관측만 나빠진 것이고,
테스트가 그 사실까지 확인합니다.
